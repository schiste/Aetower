# Aetower — Repository Audit

**Date:** 2026-09-29 · **Commit:** `f632633` (master) · **Scope:** full repo (22 Rust crates, 88 Swift files, 47 scripts, 28 docs)

**Method:** static review + empirical verification (clippy, fmt, full test suite, `swift test`, git archaeology). Findings marked **[VERIFIED]** were reproduced directly.

---

## Verdict

**B+ (engineering) / C+ (process & maintainability).**

This is unusually disciplined code written by someone who clearly knows what they are doing. `cargo fmt` and `cargo clippy --all-targets -D warnings` both pass with **zero** warnings across 96,000 lines. Zero `todo!`/`unimplemented!`. Zero `AnyView`, zero `try!`, zero `as!`, zero empty catch blocks in hand-written Swift. No committed secrets, no vendored code, no git dependencies, Sparkle EdDSA mandatory.

The problem is not the code. It is that **the safety nets are not attached**: a 202-test Swift suite that never runs, a test-isolation bug that will randomly redden CI, documentation that has drifted from shipped behavior, and 101 `unsafe` blocks with exactly one safety comment.

## Top findings

### 🔴 P0 — Act this week

**1. The entire Swift test suite never runs.** [VERIFIED]
`grep -rn "swift test" scripts/ .githooks/ .github/ docs/` → **0 hits**. 202 tests / 6,395 lines in `macos/Tests/AetowerUITests/` are never compiled or executed by CI, pre-commit, pre-push, or any script.
I ran them manually: **202 passed, 0 failed, in 180s.** They are good tests — `TrashServiceTests` covers destructive filesystem ops with fail-closed semantics. They are simply orphaned.
*Fix:* one line in `scripts/ci-local.sh:run_full_gate` after the `swift build` at `:596`.

**2. Flaky storage tests will randomly fail CI.** [VERIFIED — reproduced twice]
- Parallel run #1: `storage_summary_uses_strict_reclaim_buckets` FAILED (275 pass / 1 fail)
- Parallel run #2: **two different tests** FAILED — `storage_hygiene_generates_reclaim_actions_for_common_dev_artifacts`, `storage_hygiene_reclaimable_regression_detects_build_logs_and_caches`
- Serial run (`--test-threads=1`): **276/276 PASS**

**Root cause:** `state_store.rs:49` defines the test index directory as a process-wide `OnceLock<PathBuf>` at `$TMPDIR/aetower-storage-index-test-<pid>`. Only **3** of the **17** index-using tests call `replace_storage_index_directory_for_test`; the rest share one SQLite file. `report.rs:884` adds a global `INDEX_REPORT_SECTIONS_MEMO` keyed on a generation stamp, so cross-test contamination returns wrong results non-deterministically.
I confirmed on disk: three ~5 MB shared index DBs, one per test process.

*Fix (immediate):* `-- --test-threads=1` for `-p aetower-mcp` in `ci-local.sh:483` — mirrors what `aetower-helper` already does at `:484`.
*Fix (proper):* make `test_root()` drive the directory override, or key the memo per test.

**3. `.aethyme/` is untracked but not gitignored.** [VERIFIED]
Every sibling agent dir is ignored (`.claude/`, `.codex/`, `.cursor/`, `.aider/`). `.aethyme/` is not. It contains a live 885 KB `broker.db` (+WAL/SHM) and `generated/experience-telemetry.jsonl` with the maintainer's absolute home path. A `git add .` commits it — and it also breaks `release-preflight.sh`'s `--untracked-files=all` clean-worktree gate.
*Fix:* add `/.aethyme/` to `.gitignore`.

**4. The maintainer's home directory is published on the public website.** [VERIFIED]
`docs/mcp-tools.md:1301` and `docs/mcp-tools.examples.json:1515` contain `--arg repo_root="/Users/christophehenner/.claude/plugins/cache/..."`, and the doc is published to `aetower.dev/docs/mcp-tools/`. The same file leaks real Bluetooth MACs, a boot UUID, and a colleague's app identity.
Cause: `generate-mcp-tools-doc.py:237-240` sanitizes the tool **output** but not the tool **args**.
*Fix:* `sanitize(args)`, then scrub the committed artifacts.

**5. `master` is 101 commits ahead of `origin/master`.** [VERIFIED]
Since 2026-08-07. Combined with a **stale dependabot PR from 2026-06-03** that, if merged, would **delete `aetower-policy` and `aetower-cli`** from the workspace (`rust/Cargo.toml` diff). There is no `.github/dependabot.yml` — the config was removed or never committed while the branch persisted.
*Fix:* push master; close the stale PR; add `dependabot.yml`.

### 🟠 P1 — This month

**6. A second, weaker authorization path to privilege escalation.** `SECURITY.md:40-44` promises "client-supplied approval flags and target identities are not trusted as authorization." The MCP path honors this (one-time approval token, PID-reuse revalidation). But the FFI/UI path re-parses authority out of a free-text `reason` string at `process_action.rs:269-289`, which can set `privileged_helper_approved` and `expected_targets` and reach `osascript … with administrator privileges` (`:614`). The command itself stays allowlisted (`/bin/kill`, `/usr/bin/renice`), so this is a design-invariant violation, not arbitrary root execution. **Any widening of `plan.command` silently becomes root injection.** *Fix: delete the JSON envelope; make the context a typed FFI parameter.*

**7. FFI lock is held across SQLite `VACUUM`.** `ffi:1450` takes `self.inner.lock()` → `persistence.rs:1010` runs `VACUUM` on a multi-hundred-MB `history.db`. All 77 exported methods — including the snapshot fetch the UI polls at 1 Hz — block for the duration. Guaranteed multi-second UI freeze. Related: 29 `.expect("engine lock poisoned")` on a `std::sync::Mutex` mean one poison **permanently** bricks all 29; the correct `.map_err` pattern sits 8 lines away at `ffi:2068`.

**8. Blocking FFI + JSON decode on the MainActor.** `AppState.swift:2416-2437` calls `bridge.storageSituationJSON` and does a full `JSONDecoder.decode` on the main actor — on every Storage tab open, every cache hit, every completed scan. The correct detached implementation already exists 200 lines away (`:2682-2698`). 7 more sites decode on-main (scorecard, lsof, spindump, vmmap).

**9. Release double-notarizes.** `release-public-preview.sh` re-runs `package-macos-dmg.sh:120` and `package-macos-pkg.sh:128`, which `release.sh:40,47` already ran. Each submits a fresh `notarytool submit --wait` — so one release performs **2 DMG + 2 PKG notarizations**, roughly doubling Apple's wall-clock and quota for nothing. 5 of 12 release steps run twice.

**10. `cargo audit` is silently skipped in CI** and its ignore list diverges from `deny.toml`: `ci-local.sh:606` ignores `RUSTSEC-2025-0141` (documented in `deny.toml` with a migration plan) **and** `RUSTSEC-2026-0097` (appears exactly once in the whole repo, no rationale, not in `deny.toml`, on the `rustls` path that carries the VirusTotal API key).

**11. 101 `unsafe` blocks, 1 `// SAFETY:` comment.** Worst cluster: `aetower-collector` (48 blocks, 0 comments) with a ~35-line IOKit block **duplicated verbatim** at `:1927` and `:2338`, and a third copy in `aetower-gpu:60`. Highest risk: `storage/events.rs:276` `fsevents_callback` creates a `&mut` to caller-owned stack memory, mutates it from a CoreFoundation run-loop callback while a polling thread reads it, and never validates `event_count` against array lengths.

**12. `docs/mcp-tools.md` is stale for 5 of 48 tools** (all `aetower_storage_hygiene*`: 5 params missing on four of them, contradictory `deep_scan` description). `validate-public-claims.py:219-241` only checks the **count** (49), never names/params. The generator has **zero callers** — its own docstring claims the release checklist covers regeneration; it does not.

**13. No CI caching, no coverage, no release workflow.** Zero `actions/cache` — every run cold-builds 260 crates + Rust release dylib + Sparkle. `actions/checkout@v4` is tag-pinned, not SHA-pinned. `brew install` tools unpinned. No code coverage anywhere. And **every signed release requires one maintainer's Mac** — no CI release, no attestation.

**14. gitleaks diff-base bug.** `ci-local.sh:359-371` falls back to `origin/main`/`main`. The repo branch is **`master`**. On a new-branch push in CI (detached HEAD, no upstream), the range collapses to `HEAD..HEAD` and **the secret scan silently checks nothing**.

## What is genuinely excellent — preserve this

- **Clippy + fmt clean** across 96k lines with `-D warnings`. Rare.
- **Transport security is real**: Unix socket `0600`, dir `0700`, byte-bounded JSON-RPC framing (16 KiB header / 1 MiB body), 64-client cap, refuses to clobber a non-socket path. Tested.
- **PID-reuse/TOCTOU revalidation is actually implemented** (`process_action.rs:362-435`): re-reads the snapshot immediately before signalling, verifies start-time and executable, rejects tree drift.
- **`trusted_command` does `env_clear()`** with a comment naming the exact PATH-injection attack it prevents. All spawned binaries are absolute paths.
- **FFI has zero `unsafe`** — no hand-rolled C ABI, so no `CStr` unwrap or buffer-overflow surface. `panic = "unwind"` is deliberate and documented.
- **UniFFI drift is triple-guarded** — I regenerated the bindings and got a byte-identical result.
- **Privacy defaults are honest and enforced**: telemetry `enabled: false`, default endpoint `localhost:4318`, VirusTotal needs opt-in + API key, socket is owner-only. Only 4 hardcoded hosts in the whole Rust tree.
- **`validate-public-claims.py` is a real claims validator** (8 checks: retention, tool safety, tool count, outbound defaults, CLI bundling, published assets, URL reachability). Rare and admirable.
- **Performance budgets are measured and enforced** (`bench.rs` with real p95 + RSS thresholds, gated on pre-push).
- **Documentation tone is honest** — `known-limitations.md` and `PRIVACY.md` state limitations plainly instead of overselling. Keep this.
- **No `AnyView`, no `try!`/`as!` in app code, no Combine, no `DispatchQueue.global()`, no `.id()` misuse.** The SwiftLint custom rules are doing real work.
- **Source archive generation is excellent** — `git archive` at a pinned SHA, `gzip -n` for reproducibility, dirty-worktree refusal, published *and* byte-verified post-deploy.
- **Deliberately honest comment at `Cargo.toml:52`** explaining why panic must stay `unwind`.

## Methodology notes

Reproduced directly on this machine:
- `cargo fmt --all --check` → clean.
- `cargo clippy --workspace --all-targets --locked` → **0 warnings** (3m00s).
- `cargo test --workspace --locked` → mcp crate 275/276 (1 fail).
- `cargo test -p aetower-mcp --lib` (parallel) → 274/276, **2 different failures**.
- `cargo test -p aetower-mcp --lib -- --test-threads=1` → **276/276 pass** (465s).
- `swift test` → **202/202 pass** (180s), after `build-rust.sh` generated `module.modulemap`.
- `git rev-list --count origin/master..master` → 101.
- `git diff master origin/dependabot/cargo/...` → removes 2 workspace members.

One caveat: this machine was under heavy concurrent load (load average 35-60 from unrelated builds), which inflated wall-clock times. It does not affect the pass/fail results, all of which are deterministic given the test-threads flag.
